# tests/

Aquí viven los tests de cada spec. Cada criterio de aceptación de `docs/specs/` debería tener al menos una prueba, y los casos borde y de seguridad también.

Convención sugerida: un archivo de pruebas por spec, nombrado con su identificador (por ejemplo, `SPEC-001`), para poder rastrear qué test cubre qué criterio.
